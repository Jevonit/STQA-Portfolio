Definisi dan Tujuan Testing Plan

Apa itu Testing Plan?

Testing Plan (atau Test Plan) adalah dokumen formal yang mendeskripsikan scope, pendekatan, sumber daya, dan jadwal aktivitas testing yang akan dilakukan. Test Plan berfungsi sebagai blueprint atau roadmap untuk seluruh proses testing dalam sebuah project.

Tujuan Testing Plan

Test Plan memiliki beberapa tujuan penting dalam proses pengembangan perangkat lunak:

  • Memberikan panduan sistematis untuk seluruh aktivitas testing
  • Memastikan semua stakeholder memiliki pemahaman yang sama tentang strategi testing
  • Mengidentifikasi sumber daya (manusia, tools, infrastruktur) yang dibutuhkan
  • Mendefinisikan scope dan boundaries dari testing yang akan dilakukan
  • Menetapkan jadwal dan milestone untuk aktivitas testing
  • Mengidentifikasi risiko dan mitigasi dalam proses testing
  • Menjadi referensi untuk mengevaluasi progress testing

Catatan Penting: Test Plan yang baik dapat menghemat waktu dan biaya dengan mencegah miskomunikasi dan memastikan testing dilakukan secara efisien dan efektif.

Komponen Testing Plan (IEEE 829)

IEEE 829 adalah standar internasional untuk dokumentasi software testing. Berikut komponen-komponen utama dalam Test Plan menurut template IEEE 829:

1. Test Plan Identifier

Unique identifier untuk dokumen test plan, misalnya: "TP-BMI-001-2025". Identifier ini memudahkan referensi dan version control dokumen.

2. Introduction

Pengantar yang menjelaskan overview project dan tujuan testing. Bagian ini memberikan konteks kepada pembaca tentang apa yang akan diuji dan mengapa.

3. Test Items

Daftar lengkap fitur, modul, atau komponen yang akan diuji. Contoh untuk aplikasi BMI:

  • Input form untuk tinggi badan dan berat badan
  • Fungsi kalkulasi BMI
  • Display hasil BMI dan kategori
  • Validasi input
  • Responsivitas UI

4. Features to be Tested

Fitur-fitur spesifik yang akan menjadi fokus testing. Prioritas fitur ditentukan berdasarkan risiko dan kepentingan bisnis:

  • High Priority: Kalkulasi BMI yang akurat, validasi input
  • Medium Priority: Display hasil, kategori BMI
  • Low Priority: Styling UI, animasi

5. Features Not to be Tested

Fitur atau aspek yang secara eksplisit tidak akan diuji, dengan alasan yang jelas. Contoh:

  • Third-party library yang sudah teruji (tidak perlu test ulang)
  • Fitur yang out of scope untuk release ini
  • Aspek yang akan ditest oleh tim lain

6. Approach

Strategi dan metodologi testing yang akan digunakan:

  • Tipe testing: Unit Testing, Integration Testing, System Testing, UAT
  • Teknik testing: Black Box, White Box, atau kombinasi
  • Automation vs Manual testing
  • Test levels dan sequence

7. Item Pass/Fail Criteria

Kriteria yang jelas untuk menentukan apakah test item dinyatakan pass atau fail:

  • Pass: Semua test case dengan priority high dan medium pass
  • Pass: Tidak ada critical atau high severity bug yang open
  • Fail: Ada kalkulasi yang tidak akurat
  • Fail: Aplikasi crash atau tidak responsif

8. Suspension Criteria and Resumption Requirements

Kondisi yang menyebabkan testing ditangguhkan dan syarat untuk melanjutkan:

  • Suspension: Build tidak stabil, environment down, blocking bugs
  • Resumption: Setelah bug diperbaiki dan verified, environment sudah ready

9. Test Deliverables

Dokumen dan artifact yang akan dihasilkan dari proses testing:

  • Test Plan document
  • Test Case document
  • Test Execution Report
  • Bug Reports
  • Test Summary Report

10. Testing Tasks

Daftar task yang perlu dilakukan dalam proses testing:

  • Review requirements dan design
  • Setup test environment
  • Develop test cases
  • Execute test cases
  • Log defects dan track resolution
  • Regression testing
  • Prepare test report

11. Environmental Needs

Spesifikasi environment dan tools yang dibutuhkan:

  • Hardware: Spesifikasi komputer, mobile devices
  • Software: OS, browser, database, test tools
  • Network: Internet connection, bandwidth requirements
  • Test Data: Dataset yang diperlukan untuk testing

12. Responsibilities

Role dan tanggung jawab setiap anggota tim testing:

  • Test Manager: Overall testing strategy dan koordinasi
  • Test Lead: Supervisi test execution dan reporting
  • Test Engineer: Design dan execute test cases
  • Developer: Fix defects dan support testing

13. Staffing and Training Needs

Kebutuhan SDM dan training yang diperlukan:

  • Jumlah tester yang dibutuhkan
  • Skill set yang diperlukan
  • Training untuk tools atau teknologi baru
  • Rencana onboarding untuk anggota tim baru

14. Schedule

Timeline untuk setiap fase testing dengan milestone yang jelas:

  • Test Planning: Minggu 1
  • Test Design: Minggu 2
  • Test Execution: Minggu 3-4
  • Regression Testing: Minggu 5
  • Test Closure: Minggu 6

15. Risks and Contingencies

Identifikasi risiko dan rencana mitigasi:

  • Risk: Delay dalam development → Mitigation: Parallel test case preparation
  • Risk: Insufficient test data → Mitigation: Prepare synthetic data
  • Risk: Tool licensing issues → Mitigation: Identify alternative tools
  • Risk: Resource unavailability → Mitigation: Cross-train team members

16. Approvals

Tanda tangan dan approval dari stakeholder kunci:

  • Test Manager
  • Project Manager
  • Development Lead
  • Product Owner

Contoh: Testing Plan untuk Aplikasi BMI

1. Test Plan Identifier

TP-BMI-Calculator-001-2025

2. Introduction

Test plan ini mendeskripsikan strategi testing untuk aplikasi BMI Calculator, sebuah web application yang menghitung Body Mass Index berdasarkan tinggi dan berat badan pengguna. Tujuan testing adalah memastikan akurasi kalkulasi, validitas input, dan user experience yang baik.

3. Test Items

  • Form input (tinggi badan dalam cm, berat badan dalam kg)
  • Button "Hitung BMI"
  • Formula kalkulasi BMI: BMI = berat (kg) / (tinggi (m))²
  • Display hasil BMI (nilai numerik)
  • Kategori BMI (Underweight, Normal, Overweight, Obese)
  • Input validation dan error handling
  • Responsive design untuk mobile dan desktop

4. Approach

Testing akan dilakukan dengan pendekatan multi-level:

  • Unit Testing: Test fungsi kalkulasi BMI secara isolated
  • Integration Testing: Test interaksi antara form input dan kalkulasi
  • System Testing: Test aplikasi secara end-to-end
  • Usability Testing: Test dengan real users untuk feedback UX
  • Teknik: Kombinasi Black Box (functional) dan White Box (code coverage)

5. Pass/Fail Criteria

Pass Criteria:

  • 100% test cases dengan priority "Critical" pass
  • 90% dari semua test cases pass
  • Tidak ada critical atau high severity bugs open
  • Kalkulasi BMI akurat dengan margin error < 0.01

Fail Criteria:

  • Ada critical bug yang open
  • Kalkulasi tidak akurat
  • Aplikasi crash atau hang

6. Schedule

  • Week 1: Test Planning dan Test Case Design
  • Week 2: Test Environment Setup dan Test Execution (Functional)
  • Week 3: Usability Testing dan Bug Fixing
  • Week 4: Regression Testing dan Test Closure

7. Risks

  • Risk: Formula kalkulasi salah → Impact: High → Mitigation: Cross-verify dengan standard BMI formula
  • Risk: Browser compatibility issues → Impact: Medium → Mitigation: Test di multiple browsers
  • Risk: Invalid input tidak tertangani → Impact: High → Mitigation: Implement comprehensive validation

Kesimpulan: Test Plan yang komprehensif seperti contoh di atas memastikan testing dilakukan secara terstruktur, efisien, dan mencakup semua aspek penting dari aplikasi yang diuji.
