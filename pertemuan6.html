Definisi API Testing

Apa itu API?

API (Application Programming Interface) adalah sekumpulan protokol, tools, dan definisi yang memungkinkan aplikasi yang berbeda untuk berkomunikasi satu sama lain. API berfungsi sebagai jembatan yang menghubungkan berbagai software components atau systems. Dalam konteks web development, API sering merujuk pada REST API atau Web API yang berkomunikasi melalui HTTP/HTTPS protocol.

Apa itu API Testing?

API Testing adalah tipe software testing yang memverifikasi bahwa API berfungsi dengan benar dan memenuhi ekspektasi dalam hal functionality, reliability, performance, dan security. API testing dilakukan pada application layer atau business logic layer tanpa UI, fokus pada request dan response data.

Karakteristik API Testing

  • Testing dilakukan di level business logic, bukan UI
  • Fokus pada data exchange (request/response)
  • Menggunakan HTTP methods (GET, POST, PUT, DELETE, PATCH)
  • Memverifikasi response codes, headers, dan body
  • Dapat dilakukan secara automated
  • Testing dilakukan lebih awal dalam development cycle

Perbedaan API Testing vs UI Testing

API Testing:

  • Tests business logic layer
  • Tidak memerlukan GUI
  • Lebih cepat untuk execute
  • Lebih stabil (tidak terpengaruh UI changes)
  • Dapat test sebelum UI ready

UI Testing:

  • Tests presentation layer
  • Memerlukan fully functional UI
  • Lebih lambat untuk execute
  • Prone to failures karena UI changes
  • Dilakukan setelah UI development complete

Best Practice: Testing pyramid merekomendasikan lebih banyak API/integration tests dibanding UI tests karena API tests lebih cepat, reliable, dan maintainable.

Keunggulan API Testing

Mengapa Pengujian API Penting?

API testing memberikan berbagai keuntungan penting dalam software development:

1. Early Testing

API testing dapat dilakukan segera setelah business logic selesai dibuat, bahkan sebelum UI development dimulai. Ini memungkinkan early bug detection dan mempercepat development cycle secara keseluruhan.

2. Language Independent

API testing tidak terikat pada bahasa pemrograman atau framework tertentu. Kita dapat test API yang dibuat dengan Java menggunakan testing tools berbasis JavaScript atau Python, selama API menggunakan standard protocol seperti HTTP.

3. Faster Execution

API tests jauh lebih cepat dibanding UI tests karena tidak perlu rendering UI dan menunggu browser loading. Satu API test bisa dijalankan dalam hitungan milidetik, sementara UI test bisa memakan beberapa detik.

4. Better Test Coverage

Dengan API testing, kita dapat test berbagai scenarios dan edge cases yang sulit atau tidak mungkin ditest melalui UI. Misalnya testing dengan data volume besar atau testing error scenarios yang jarang terjadi di UI.

5. Easier Maintenance

API tests lebih stable dan mudah dimaintain karena API contracts cenderung lebih stabil dibanding UI. UI changes sering terjadi karena redesign atau UX improvements, tapi API endpoint jarang berubah.

6. Integration Testing

API testing sangat efektif untuk integration testing karena memverifikasi komunikasi antara berbagai services atau components dalam microservices architecture.

7. Performance Testing

API testing memudahkan performance dan load testing karena dapat mengirim banyak requests secara parallel untuk simulate high traffic tanpa overhead dari UI rendering.

8. Security Testing

API adalah entry point untuk data dan functionality, sehingga API testing penting untuk memverifikasi security aspects seperti authentication, authorization, data encryption, dan input validation.

ROI: Investment dalam API testing memberikan return yang tinggi karena bugs yang ditemukan di level API jauh lebih murah untuk diperbaiki dibanding bugs di production.

Tools untuk API Testing

Postman

Postman adalah tool paling populer untuk API testing dengan interface yang user-friendly. Postman menyediakan features lengkap untuk development, testing, dan documentation API.

Fitur Utama Postman:

  • Intuitive GUI untuk membuat dan mengirim HTTP requests
  • Collections untuk organize related requests
  • Environment variables untuk manage different environments
  • Test scripts menggunakan JavaScript
  • Automated testing dengan Newman (command-line runner)
  • Mock servers untuk development
  • API documentation generation
  • Collaboration features untuk team
  • Pre-request scripts untuk setup
  • Response visualization (JSON, XML, HTML)

Keunggulan Postman:

  • Free untuk individual use dengan features yang powerful
  • Easy to learn dengan learning curve yang rendah
  • Cross-platform (Windows, Mac, Linux)
  • Large community dan extensive documentation
  • Integration dengan CI/CD pipelines

SoapUI

SoapUI adalah tool untuk testing SOAP dan REST APIs dengan focus pada functional testing, security testing, dan load testing.

Fitur Utama SoapUI:

  • Support untuk SOAP dan REST APIs
  • Drag-and-drop test creation
  • Data-driven testing
  • Security testing (SQL injection, XSS)
  • Load testing dan performance testing
  • Assertion untuk validation
  • Groovy scripting untuk advanced scenarios

Keunggulan SoapUI:

  • Comprehensive testing capabilities (functional, security, load)
  • Strong support untuk SOAP services
  • Open source version available
  • Enterprise features untuk professional use

Perbandingan: Postman vs SoapUI

Postman: Best untuk REST APIs, modern interface, easier to use, better untuk development dan quick testing.

SoapUI: Best untuk SOAP APIs, comprehensive testing features, better untuk complex test scenarios dan security testing.

Konsep Dasar: Anatomi Request dan Response

HTTP Request

HTTP Request adalah message yang dikirim dari client ke server untuk request data atau action. Request terdiri dari beberapa komponen:

1. HTTP Method

Method menentukan jenis operasi yang akan dilakukan:

  • GET: Retrieve data (read operation)
  • POST: Create new resource
  • PUT: Update entire resource
  • PATCH: Update partial resource
  • DELETE: Delete resource

2. URL/Endpoint

URL menentukan resource yang akan diakses. Contoh:

  • https://api.example.com/users
  • https://api.example.com/users/123
  • https://api.example.com/products?category=electronics

3. Headers

Headers berisi metadata tentang request:

  • Content-Type: Format data yang dikirim (application/json, application/xml)
  • Authorization: Token untuk authentication (Bearer token, API key)
  • Accept: Format response yang diinginkan
  • User-Agent: Informasi tentang client

4. Body

Body berisi data yang dikirim ke server (untuk POST, PUT, PATCH requests). Format umum adalah JSON atau XML.

Contoh Request Body (JSON):

{
    "name": "John Doe",
    "email": "john@example.com",
    "age": 30
}

5. Query Parameters

Parameters yang ditambahkan di URL untuk filtering atau pagination:

GET https://api.example.com/products?category=electronics&page=1&limit=10

HTTP Response

HTTP Response adalah message yang dikirim dari server ke client sebagai jawaban dari request. Response terdiri dari:

1. Status Code

Status code mengindikasikan hasil dari request:

  • 2xx Success: 200 OK, 201 Created, 204 No Content
  • 3xx Redirection: 301 Moved Permanently, 302 Found
  • 4xx Client Error: 400 Bad Request, 401 Unauthorized, 404 Not Found
  • 5xx Server Error: 500 Internal Server Error, 503 Service Unavailable

2. Response Headers

Headers berisi metadata tentang response:

  • Content-Type: Format response data
  • Content-Length: Ukuran response body
  • Set-Cookie: Cookie yang di-set oleh server
  • Cache-Control: Caching directives

3. Response Body

Body berisi data yang dikirim dari server. Format umum adalah JSON.

Contoh Response Body (JSON):

{
    "id": 123,
    "name": "John Doe",
    "email": "john@example.com",
    "age": 30,
    "created_at": "2025-10-29T12:00:00Z"
}

REST API Convention: REST APIs menggunakan HTTP methods secara semantic: GET untuk read, POST untuk create, PUT/PATCH untuk update, DELETE untuk delete. Status codes juga digunakan secara konsisten untuk indicate hasil operasi.

Operasi Dasar di Postman

Setup dan Interface

Installation:

  1. Download Postman dari https://www.postman.com/downloads/
  2. Install aplikasi (tersedia untuk Windows, Mac, Linux)
  3. Create account atau sign in
  4. Explore workspace dan interface

Interface Utama:

  • Sidebar: Collections, Environments, History
  • Request Builder: Method, URL, Params, Headers, Body
  • Response Panel: Body, Headers, Cookies, Test Results

Membuat dan Mengirim Request

Langkah-langkah Dasar:

  1. Click "New" atau "+" untuk membuat request baru
  2. Pilih HTTP method (GET, POST, PUT, DELETE)
  3. Masukkan URL endpoint
  4. Configure headers jika diperlukan
  5. Add request body untuk POST/PUT (pilih format: JSON, form-data, etc)
  6. Click "Send" button
  7. Observe response di panel bawah

Working with Collections

Collections adalah cara untuk organize related requests:

  • Create collection untuk group requests by feature atau module
  • Save requests ke collection untuk reuse
  • Add folders untuk organize hierarchically
  • Share collections dengan team members
  • Run entire collection untuk automated testing

Environment Variables

Environment variables memudahkan management different environments (dev, staging, production):

  • Create environment (e.g., "Development", "Production")
  • Add variables (base_url, api_key, auth_token)
  • Use variables dengan syntax {{variable_name}}
  • Switch environments dengan dropdown di top-right

Contoh Environment Variables:

// Development Environment
base_url: https://api-dev.example.com
api_key: dev_key_12345

// Production Environment
base_url: https://api.example.com
api_key: prod_key_67890

Writing Tests

Postman allows writing test scripts dalam tab "Tests" menggunakan JavaScript:

Contoh Test Script:

// Test status code
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

// Test response time
pm.test("Response time is less than 500ms", function () {
    pm.expect(pm.response.responseTime).to.be.below(500);
});

// Test response body
pm.test("Response has user data", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.have.property('name');
    pm.expect(jsonData.name).to.eql('John Doe');
});

Studi Kasus: Testing dengan API Publik

Contoh 1: GET Request - JSONPlaceholder API

JSONPlaceholder adalah fake REST API untuk testing dan prototyping.

Endpoint: https://jsonplaceholder.typicode.com/users

Langkah Testing di Postman:

  1. Method: GET
  2. URL: https://jsonplaceholder.typicode.com/users
  3. Click Send

Expected Response:

[
    {
        "id": 1,
        "name": "Leanne Graham",
        "username": "Bret",
        "email": "Sincere@april.biz",
        ...
    },
    ...
]

Test Script:

pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response is an array", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.be.an('array');
});

pm.test("Array has 10 users", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.have.lengthOf(10);
});

pm.test("First user has required fields", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData[0]).to.have.property('id');
    pm.expect(jsonData[0]).to.have.property('name');
    pm.expect(jsonData[0]).to.have.property('email');
});

Contoh 2: GET Request dengan Parameter - Specific User

Endpoint: https://jsonplaceholder.typicode.com/users/1

Langkah Testing:

  1. Method: GET
  2. URL: https://jsonplaceholder.typicode.com/users/1
  3. Click Send

Test Script:

pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("User ID is 1", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData.id).to.eql(1);
});

pm.test("User has name", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData.name).to.exist;
    pm.expect(jsonData.name).to.be.a('string');
});

Contoh 3: POST Request - Create New Post

Endpoint: https://jsonplaceholder.typicode.com/posts

Langkah Testing:

  1. Method: POST
  2. URL: https://jsonplaceholder.typicode.com/posts
  3. Headers: Content-Type: application/json
  4. Body (raw JSON):
{
    "title": "Test Post",
    "body": "This is a test post content",
    "userId": 1
}

Expected Response (Status: 201 Created):

{
    "id": 101,
    "title": "Test Post",
    "body": "This is a test post content",
    "userId": 1
}

Test Script:

pm.test("Status code is 201", function () {
    pm.response.to.have.status(201);
});

pm.test("Post was created", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.have.property('id');
    pm.expect(jsonData.id).to.be.a('number');
});

pm.test("Post has correct data", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData.title).to.eql('Test Post');
    pm.expect(jsonData.userId).to.eql(1);
});

Contoh 4: PUT Request - Update Post

Endpoint: https://jsonplaceholder.typicode.com/posts/1

Langkah Testing:

  1. Method: PUT
  2. URL: https://jsonplaceholder.typicode.com/posts/1
  3. Headers: Content-Type: application/json
  4. Body:
{
    "id": 1,
    "title": "Updated Title",
    "body": "Updated content",
    "userId": 1
}

Contoh 5: DELETE Request - Delete Post

Endpoint: https://jsonplaceholder.typicode.com/posts/1

Langkah Testing:

  1. Method: DELETE
  2. URL: https://jsonplaceholder.typicode.com/posts/1
  3. Click Send

Expected Response: Status 200 OK atau 204 No Content

Test Script:

pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response confirms deletion", function () {
    // JSONPlaceholder returns empty object on delete
    var jsonData = pm.response.json();
    pm.expect(Object.keys(jsonData).length).to.eql(0);
});

Practice: JSONPlaceholder (https://jsonplaceholder.typicode.com/) dan ReqRes (https://reqres.in/) adalah API publik yang sangat baik untuk learning dan practice API testing. Keduanya menyediakan fake data dan support semua HTTP methods.
